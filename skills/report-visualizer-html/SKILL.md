# Report Visualizer — HTML（报告 → HTML 可视化）

## 1. 角色与边界

以 **Report Visualization & Information Design Specialist** 身份工作。任务是把已有研究/分析/案例/知识文档转换为**单文件、自包含、响应式**的 HTML 可视化页面，目标是"让读者在 1–3 分钟内理解报告核心，同时允许深入探索"。

**本 skill 不是研究代理。** 除非用户明确要求，否则：
- 不开展新调研、不重复核实输入中已有的数据
- 不新增市场/竞品/社媒数据、不引入输入之外的事实
- 不编造数字、不估算缺失值、不修改既有数值
- 不把推断写成事实、不删除重要来源标注

一次任务的完整循环：**Understand → Structure → Visualize → Present**。

## 2. 输入兼容

输入形态：本地文件路径（.md/.txt/.html/纯文本）、粘贴文本、对话内长文本。docx/pdf 类输入需先用文档处理工具抽取为文本，再进入本流程。

内容结构分三类，全部支持，无需用户预重构：

- **A. Executive Summary + Detailed Analysis + Structured Data**
- **B. Executive Summary + Detailed Analysis**
- **C. 其他研究 / 分析 / 案例文档**

**结构化数据检测**：通读时留意 YAML/JSON fenced block。典型信号：根键 `research:` 且含 `evidence_type` / `source`（SRC ID）字段体系、`sources:` Source Registry、`metadata: research_date` 等机器可读键。

- 存在结构化数据 → 以其为**主要结构化来源**，报告正文为上下文（补足叙事与解释）。
- 不存在 → **直接从正文抽取结构**，绝不要求用户先重构报告来适配。

## 3. 工作流程

### Step 0 · 通读并分类
完整读取输入。判断 A/B/C、是否有结构化数据层、Source Registry 在哪（通常在文末）、报告语种（**HTML 默认与输入同语种**，如中文报告 → 中文 HTML）。

### Step 1 · 提炼核心
先回答：报告在讲什么？最重要的结论是什么？3–5 个最关键的发现是哪些？同时识别：关键关系、值得对比的对象、重要指标、时间线、支撑证据。

### Step 2 · 信息架构
确立视觉层级，优先级固定：

> **Core Insight（核心洞察）> Supporting Evidence（支撑证据）> Detailed Explanation（详细说明）**

首屏必须让读者直接获得三件事：① 这是关于什么的报告；② 最重要的结论；③ 3–5 条关键发现。详情在首屏之下**渐进披露**。禁止把报告按段落机械搬进 HTML（那是排版，不是信息设计）。

### Step 3 · 组件选型
依据**实际内容**从组件库中选择（完整配方见 `references/design-system.md`）：

KPI 卡 / Insight 卡 / Timeline / Comparison matrix / Funnel / Flow diagram / Relationship map / Bar & line chart（内联 CSS）/ Table / Quote 卡 / Product 卡 / Customer segment / Campaign 卡 / Source 面板 等。

**默认图表规则（防退化，必须遵守）**：
- 凡报告出现 **≥3 条同维度可比较的定量数据**（占比/份额/排名/粉丝/评分/价格/数量/金额/时间点），**必须用图表**呈现（水平条形组 `.bars` / 垂直柱状 `.vcols` / 环形 `.donut` / 漏斗 `.funnel` / 层流 `.engine`）——不允许退化为纯文字列表或每行一个孤立 KPI。
- 图表 CSS **已全部内置在模板**（Chart suite + COPY-ME 注释示例），直接套 class，不要自造样式、不要因为"要写 CSS 麻烦"而省略图表。
- 表格只保留给"需要逐行多列精确对照"的场景；精确单维对比用条形图。
- 例外：仅 1–2 个孤立数字（用 KPI）、口径不可比的混合数据、纯表格语义的数据。
- 常见映射速查：地区/渠道/份额/平台占比 → `.bars`；价格阶梯/多档指标 → `.vcols`；单占比强调 → `.donut`；渠道转化/层级 → `.funnel`；growth_engine → `.engine` 层流；里程碑 → `.timeline`；社交矩阵多字段 → 表格。

### Step 4 · 品牌 / 主题视觉
- 报告关于**具体品牌**：可参考该品牌官网或已知品牌资料提取**视觉身份**（主色 + 兼容次级色 + 风格），并保持高可读性。此动作仅限视觉用途，不是研究。
- 报告**非品牌专属**：使用中性专业视觉系统（见 `references/design-system.md` 视觉系统节）。
- **不发明品牌身份**；用户给了色值/风格则以用户为准。

### Step 5 · 生成 HTML
1. 先读 `assets/template.html`，以它的骨架、设计令牌与基础样式为基底，在其上**填充语义化内容**（hero / 关键发现 / 各分析章节 / 来源面板），不要自造一套新样式体系。模板已内置 **Chart suite CSS**（bars/vcols/donut/funnel/engine + c1-c5 色板 + grid3/cols2）与 **COPY-ME 示例注释**——凡可比较定量数据直接套用；模板 CSS 不够时再按 `references/design-system.md` §4.8 增补。
2. 遵守输出契约（第 5 节）与设计系统约束：
   - 单文件自包含：内联 `<style>`（+ 极少量内联 JS），无外部框架/字体依赖，加载快，可离线打开。
   - 响应式：桌面 + 移动均可用；明暗双主题用 CSS 变量 + `prefers-color-scheme`（模板已内置）。
   - 图表用内联 CSS / 纯 SVG 实现，不引第三方库（模板含全套 Chart suite）。
   - 语义化标签与标题层级；`<html lang>` 与报告语种一致。
   - **排版三铁律**（详见 `references/design-system.md`）：
     - `.lead`（核心结论段）必须 `width:100%` 占满内容区、与上下文同宽，不得设 `max-width:xxch`；且以「结论卡片」呈现——`background:var(--surface); border:1px solid var(--border); border-left:4px solid var(--accent); border-radius:0 var(--radius) var(--radius) 0; padding:14px 18px`（细边框 + 左侧 accent 线条勾勒 + 浅背景 + 右侧圆角）；文本内关键短语/数字用 `<b>` 加粗（`.lead b{font-weight:750}`），颜色用 `var(--text)`。
     - KPI 卡组 `.kpi-grid` 用 flex 单行等宽（`flex-wrap:nowrap` + 每卡 `flex:1 1 0`），无论几张都一行铺满、等宽，不得让第 N 张折到第二行；卡片内部三部分「小标题/大数字/解释说明」各自第一行对齐：① `.kpi-value` 只放数字+计量单位、前后不加描述文字（「约 ¥400 亿」→「¥400 亿」、日期只留年月、评分列确切值不列范围）；② `.kpi-label` 设 `min-height` 统一行高让数字同基线；③ `.kpi-value` 必须 `white-space:nowrap` 单行不折两排；④ `.kpi-note` 顶部对齐（`border-top` 分隔，不用底部对齐/强行等高）。
     - 品牌速览区按内容量分组：短文字块（商业模式 / 渠道结构）用 `.cols2` 一行两列，时间线（里程碑）另起一行全宽并用横向 `.timeline-h` 铺开——禁止三块竖排等高导致空白。**时间线内容长（历史久/节点多，约 ≥6 项）时 `.timeline-h` 自动换行铺满多行直至完整呈现，禁止 `overflow-x` 横向滚动拖动**（模板已默认 `flex-wrap:wrap`；详见 design-system §4.5 时间线）。
3. 证据分级保留：原报告标注了 `FACT/OBSERVATION/INFERENCE/ESTIMATE/UNKNOWN`（含复合如 `FACT/OBSERVATION`）时，在对应条目上用**证据徽章**呈现，并在首屏附近给**图例**。原文没分级就不要给数据点强行贴标签。
4. 引用保留：定量数据点旁放**小型 Source chip**（如 `SRC-004` 或 `[来源名, url]`），可点击链接；完整 Source Registry（含 id/name/url/access_date）放**页尾折叠区（`<details>`）**，不占首屏注意力但可追溯。
5. **构建卫生（实测易踩）**：
   * **超长 HTML 分两次落盘**。信息密集的成品常在 50–70KB 以上，单次生成（Write 一次写完全文）会被模型输出上限截断、末尾内容丢失且表面"成功"——先 Write 写完 `<head>`+样式+前半章节并以唯一占位注释（如 `<!--PART2-->`）收尾，再用 Edit 把占位替换为后半章节，最后 `wc -l` + 标签配平脚本复核闭合。
   * **无头核验用整页高度截图**。`chrome --headless --screenshot --window-size=1280,N`（N 取页面总高）才能拿到整页；URL 片段（`x.html#section`）**不会**让 `--screenshot` 滚动到锚点，会重复截到顶部。截完用 PIL 竖向切段逐段目检（长图直接 Read 会被降采样到看不清）。

### Step 6 · 落盘与命名（Report Library Convention）

产物位置按**报告库约定**推导，让 HTML 与源报告、图片集始终同属一个品牌目录：

1. **输入已在品牌目录内**（如 `BrandA/branda_report_2026-09-08.md`）：沿用该目录与文件名前缀，只换扩展名 → 输出 `BrandA/branda_report_2026-09-08.html`。
2. **输入为平铺文件**（未归入品牌目录，如 `BrandA_Growth_Research_2026-09-08.md`）：推导标准名 `{brand_slug}_report_{YYYY-MM-DD}.html` 并放入品牌目录 —— `brand_slug` 为品牌名小写、去空格与特殊字符（`Acme Corp` → `acmecorp`、`Beta Labs` → `betalabs`）；日期取报告的数据截止日/研究日期（缺失时用今天）；品牌目录不存在则先建。
3. **非品牌专属报告**（行业分析、通用研究等无明确品牌所有者）：退回 `<输入文件名>.html`，与输入同目录。
4. **覆盖规则**：同品牌同日期的 HTML 视为同一报告的新版本，**直接覆盖**；只有用户明确要求保留旧版时才加后缀。
5. 用户显式指定路径/文件名时，一律以用户为准。

**字符规范**：只用小写字母、数字、`_`、`-`、`.`；禁空格与中文文件名。

写完后用浏览器预览检查渲染（若有截图工具则截图核对首屏与移动端）再交付；若工作区有报告索引文件（如 `INDEX.md`），确认该 HTML 一行已记录（无则补）。

**交付前两项机器自检**（都跑，别只靠肉眼）：
1. **着色语义**：`python scripts/audit_chart_colors.py <report.html>` —— 逐条回答「这个颜色在告诉读者什么」，答不上来的改回主题色（见 §4.8 着色语义）。
2. **色板真的生效**：用无头浏览器 `getComputedStyle` 抽查一条 `.bar-fill.c2` 的实际 `backgroundColor` 是否与主题色不同 —— 只写 `.c2` 会被 `.bar-fill` 覆盖导致全图同色，且不报错。

## 4. 铁律（源完整性与零新增）

- **只做转换，不做研究**：输入是唯一事实源。绝不"顺手补个数据/竞品/行业均值"。
- **数值零改动**：原样呈现。确需换算/格式化（如 21.74 亿元人民币 → ¥2.17B）时，HTML 中标明换算并同时保留原口径数值与单位。
- **区分事实与分析**：输入中的证据分级标签必须原样保留并可视化区分；推断（INFERENCE）永远不表述为事实；未验证项保留 UNKNOWN。
- **引用可追溯**：定量数据点带 Source ID + 可点击链接。输入已有 Source Registry 就**沿用其 ID 与 url**，不新建 ID、不为美化引用而做额外检索；输入没有 registry 时，用原文来源标注（来源名 + url）形式呈现。
- **缺失即留白**：报告没写的 = 页面里不编造；宁可显示为"报告未披露"也不杜撰。
- **对外口径清理**（HTML 常被当作对外 / 作品集页面交付）：生成后**再通读一遍**，把"研究过程的内部痕迹"改成中性陈述或删掉，典型四类：
  1. **工具 / 流程自指**：skill、framework、prompt、自动化脚本名称 → 删除或改为「研究方法」之类中性表述；
  2. **流程语**：`Modash Requirement（必查 · 已查）`、`实际打开的页面：dji.com、store.dji.com`、`本研究的抓取口径`、`人工检索` → 改为观察结论（如「创作者合作收录情况」「页面结构观察」），保留事实、去掉过程；
  3. **机器可读数据层**：fenced YAML / JSON（PART 3 结构化数据）→ HTML 里不呈现，只从其中提取来源用于来源面板；
  4. **本地路径 / 密钥 / token / 环境信息** → 一律删除。
- **个人信息边界**：作者署名（byline）**按用户指示处理**（要求署名就署名、未提供则省略）；除此之外**不引入任何关于作者的私人信息**——工作经历、任职公司、从业年限、个人背景等。输入报告里本来就有的照搬即可，输入里没有的绝不添加。

## 5. 输出契约（HTML 结构）

- **Header / Hero**：报告主题、研究对象、日期与证据口径提示、核心结论 Takeaway、3–5 关键发现（首屏）。
- **报告主标题（跨介质统一 · 强制）**：主标题（Hero `h1`）文案固定为 **`品牌名：一句总结性描述`**：
  1. **品牌名在最前**，紧跟**中文全角冒号「：」**，冒号后跟**一句话总结性描述**（结论 / 定位 / 增长机制，写成陈述句，不写成问句、不出现第二层冒号）。
  2. 品牌名写法 `英文名 中文名` 或 `中文名（英文名）`，与该报告其余部分的统称一致；非品牌报告（行业 / 主题研究）用研究对象或主题名。
  3. 描述**建议 8–28 字**，一句话说完；**日期、报告类型、"深度研究"等字样一律不进主标题**（放 `kicker` 与 meta chips）。
  4. **同一份报告若同时产出 HTML 与 PDF 两版，必须逐字使用同一个标题**，不得因介质不同改写措辞。确需为版式调整时，只允许在**不改动文字与标点**的前提下调字号 / 换行，且两处同步。
  5. **先后生成时后写方直接沿用先写方的标题文案**；用户指定以某一版为准时，以用户指定版为准，并把另一版同步改齐。
  6. `<title>` 与 Hero `h1` 使用同一文案（`<title>` 可再附"· 报告类型 · 日期"，但 `h1` 部分须逐字一致）。
  7. 正例：`Nike：从批发分销转向 DTC 直营的增长重构`、`Patagonia：以环保主张构建的高溢价 DTC 品牌`；反例：`从批发分销转向 DTC 直营：Nike 的转型是怎么做成的`（品牌名不在前）、`Nike 2026 深度研究`（无冒号、非总结句）。
- **正文章节**：按信息架构渐进展开（关键发现 → 支撑证据/章节分析 → 细节），可视化组件内嵌其中。
- **Evidence & Sources**：页尾 `<details>` 折叠的 Source Registry 或来源列表 + 证据分级图例。
- **Footer**：数据截止/研究日期与口径提示（保留报告原 note），生成说明。
- 全程保证：清晰视觉层级、数字可溯源、证据分级可见、响应式。

## 6. 最终质量检查（输出前逐项过）

- [ ] 首屏是否讲清三件事：报告主题、最重要结论、3–5 关键发现？
- [ ] **主标题格式与跨介质一致**：Hero `h1` 是否为 `品牌名：一句总结性描述`（品牌名在前 + 中文全角冒号 + 陈述句描述，无日期 / 报告类型字样）？`<title>` 与 `h1` 是否同文案？若同一报告的 PDF 版已存在，两者主标题是否**逐字一致**（不一致则改齐，用户指定版优先）？
- [ ] 最重要洞察是否视觉占主导？次要内容是否未抢注意力？
- [ ] 每个关键数字是否可溯源（Source chip / SRC ID / 链接）？Source Registry 是否完整保留（含 access_date）？
- [ ] FACT / OBSERVATION / INFERENCE / ESTIMATE / UNKNOWN 区分是否保留且带图例？是否没有给未分级数据强贴标签？
- [ ] 是否避免发明任何信息、避免逐段复制报告？
- [ ] 视觉层级与组件选择是否合理（每个组件都有其用途）？
- [ ] **图表完备性**：每个 ≥3 条的可比较定量数据集是否都用了图表（bars/vcols/donut/funnel/engine），而非纯文字/孤立 KPI？是否仍有"看似可上图却只排列表格或列表"的区块？
- [ ] **图表正确性**：每张图的数据点是否原样显示真实数值文本、柱长仅为比例示意并加 `chart-note`（含"按比例示意"口径 + 证据徽章 + SRC 来源）？宽度换算是否正确（值÷组内最大×100%）？**多序列色板是否真的生效**（`.c2`… 必须写 `.bar-fill.c2` / `.vcol .vbar.c2` 复合选择器；只写 `.c2` 会被 `.bar-fill` 覆盖导致全图同色，且不报错）？
