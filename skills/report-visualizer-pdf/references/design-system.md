# Design System & Print Reference（A4 PDF 设计系统与实现参考）

配合 `SKILL.md` 的 Step 3–7 使用。生成 A4 HTML 前阅读本文件；产出必须遵守这里的几何、分页、令牌与配方约束。骨架以 `assets/template-a4.html` 为基底。

> **与 `report-visualizer-html` 的关系**：视觉语言、色彩、字体层级、图表语言、Card style、Source style **完全同源**；页面尺寸、grid、section 高度、滚动行为**刻意不同**。凡本文件与 HTML skill 冲突之处，**以本文件为准**（PDF 优先）。

## 1. A4 版式几何

| 项目 | 规格 | 说明 |
|---|---|---|
| 页面 | **A4 纵向 210 × 297 mm**（595.3 × 841.9 pt） | `@page { size: A4 }`，由 `html_to_pdf.cjs` 保证 |
| 页边距 | 上 17mm / 左右 15mm / 下 22mm | 下边距 ≥22mm 是为页脚页码留位（Chrome 把页脚放在页面底缘上方约 6mm 处） |
| 正文区 | 180 × 258 mm（约 510 × 731 pt） | = 页面减页边距；**一切内容必须收在此区内** |
| 单页容量 | 约 40–44 行正文 | 10.5pt × 1.62 行高；用于估算页数，不作为硬约束 |
| 单一信息流 | 无分栏、无绝对定位版块 | A4 连续阅读优先；需要并排时用 `.grid3` / `.cols2` 内含卡片 |

**关键实现事实（已在 Chrome/Edge headless 实测）**：

1. CSS `@page { margin }` **优先于** CDP `marginTop/Bottom/Left/Right` 参数 —— 因此边距只在 CSS 里定义一次，渲染脚本传 0，避免"双份边距"。
2. 页脚由渲染脚本的 `footerTemplate` 注入，渲染在**页边距区域**内（不在正文流里），逐页重复，`.pageNumber` / `.totalPages` 自动填充。
3. Chrome 不支持 `@page` 的 margin box（`@top-center` 之类）与 `counter(page)`。**页码只能来自脚本页脚**，不要试图用 CSS 计数器做页码。

## 2. 字号体系（打印专用 · pt）

用 **pt** 而非 `rem` / `clamp()`：PDF 是固定介质，视口单位与 `clamp()` 的 vw 部分在打印下没有意义。

| 层级 | 字号 | 行高 | 颜色 |
|---|---|---|---|
| 报告主标题 h1（第 1 页） | 24–26pt | 1.25 | `--text`，字重 800 |
| 章节标题 h2 | 14.5–15.5pt | 1.3 | `--text`，字重 750 |
| 卡片标题 h3 | 11–12pt | 1.35 | `--text`，字重 700 |
| 正文 | **10.5pt** | 1.62 | `--text` |
| 次要说明 / note | 9pt | 1.55 | `--muted` |
| 表格 | 9.5pt | 1.45 | `--text` |
| 徽章 / chip | 7.5pt | 1 | 语义色 |
| KPI 大数字 | 19–22pt | 1.1 | `--text`，tabular-nums |
| kicker / 页眉标签 | 8pt，字距 .14em，大写 | 1 | `--muted` |
| 页脚 | 8pt | 1.4 | `--muted` |

**字号下限铁律**：正文 ≥10pt，表格 ≥9pt，注释 / 页脚 ≥7.5pt。**任何 ≤7pt 的文字在打印稿上不可读**——内容放不下时，先删冗余、再重构布局、最后才动字号，且不得突破下限。

> **同属注释级的元素一律 ≥7.5pt**：证据徽章 `.ev` / `.badge`、来源 chip `.src-chip`、图表轴标签与 `small` 副标、`.enode b` 等小标签，适用同一下限。模板 `.ev` 原为 7pt（与本节字号表自相矛盾），**2026-09-16 已校正为 7.5pt**。生成后建议用正则扫一遍：`re.findall(r'font-size\s*:\s*([0-9.]+)pt', html)`，断言无 <7.5 的取值。（注：`em` / `%` 继承值与行高不受此限，可自由用来省纵向空间——**收紧行高与条目间距是合规的降高手段，字号不是**。）

## 3. 分页规则与打印铁律

### 3.1 分页保护（模板已内置工具类）

```css
.avoid-break{break-inside:avoid;page-break-inside:avoid}
.keep-with-next{break-after:avoid;page-break-after:avoid}
.page-break{break-before:page;page-break-before:always}
```

* **卡片 / 图表 / 时间线 / 引用块 / 表格行组**：挂 `.avoid-break`。
* **所有标题 h2 / h3**：挂 `.keep-with-next`，防止标题孤悬页底。
* **AI 不要用 `page-break-before` 手工指定章节分页**（§11 明令）。仅在大章节强制新起一页确有编辑价值时用 `.page-break`，且要确认不会留下大片空白。
* `orphans:2; widows:2` 设在全文档层，避免单行孤行。

### 3.2 长表格

* `thead { display: table-header-group }` → 表头跨页自动重复。
* `tr { break-inside: avoid }` → 单行不被拆开。
* 列宽用 `<colgroup>` 或百分比；**禁止 `overflow-x:auto`**（PDF 里没有滚动条，溢出即裁切）。
* 单元格文本 `overflow-wrap:anywhere`。

### 3.3 Chrome 打印已知坑（必读）

| 坑 | 表现 | 对策 |
|---|---|---|
| `overflow-x:auto` | 溢出部分被直接裁掉 | 不用横向滚动；宽度必须自适应 |
| `position:sticky` | 打印下失效 / 错位 | 不用 |
| `position:fixed` | 在 Chrome 打印中会**每页重复** | 不要用它当"页脚"，用脚本页脚 |
| `<details>` 折叠 | 折叠内容打印时不出现 | 来源等必需内容**不要**折叠 |
| `100vh` / `vw` | 打印无视口，尺寸错乱 | 全部改用 mm / pt / % |
| 深色主题媒体查询 | PDF 可能输出深色底 | 深色主题只在 `@media screen` 内生效 |
| 背景色丢失 | 卡片 / 图表底色变白 | 渲染脚本已开 `printBackground`；不要依赖"浏览器默认会打印底色" |
| 超高单块（> 260mm） | 无法容纳，被强制切割 | 单块高度上限 ≈ 250mm，超长内容拆成多块 |
| flex 容器跨页 | 分页发生在 flex 内部时不可控 | **只有卡片内部才用 flex/grid**；参与分页的一级容器保持块级（`.card`、`section`） |
| 视口字号 `clamp(…vw…)` | 打印时按 A4 宽度取中间值，结果随机 | 用 pt 固定值 |
| **全局**给 `caption` / `thead` 加 `break-after:avoid` | 全文档版式大范围重排，实测页数 15 → 17 且新增空白页 | 别全局改；长表跨页靠 `thead{display:table-header-group}` 已足够。若只想去掉"表头孤悬页底"，改在**单个**表格上局部处理 |
| `columns:2` 用在超长列表上 | 打印下分栏平衡可能不完美，偶见左右列高不等 | 仅用于 Sources 这类"条目多、每条短"的清单；正文段落不要分栏 |

### 3.4 空白控制

* 避免"整块搬到下一页"造成的大片空白：检查每块高度，若某块 > 页面剩余高度的一半且频繁跳页，把该块拆成两个更小的块。
* `.avoid-break` 不要滥用在大容器上（例如整节包一个 `.avoid-break` 会把整节推走）。
* 允许章节自然跨页；**阅读连续性 > 固定页数**。
* **分节边界留白是正常现象，不要为填满而压字号。** 实测（一份含长 Finding 的报告）：`section header + 长 Finding` 作为一个 avoid-break 分组，在分节处会让上一页底部留下约 1/3 页空白；下一节从新页开始，视觉上等同于"章节另起页"，在编辑设计上可接受。
* **降低分组高度的正道是把长证据列表拆成两列**：把 `ul.evidence` 的 4 条拆成 `cols2` 里的两个 `ul.evidence`（各 2 条），分组高度可降约 1/3，是最有效的"少留白"手段，且不动字号、不删内容。
* **不要反复试探自动分页**：实测即便几何上剩余空间足够（如余 107mm、分组 95mm），Chrome 仍可能把 `章节标题 + 长 Finding` 整体推到下一页。与其微调 margin 反复试，不如调整分组高度或接受该处断页（每次试都要重新渲染 + 目检，成本远高于收益）。
* **最后 1–2 页偏空是正常的**（Sources 附录 + 收尾说明）；但要避免"整页只放收尾说明"的孤尾页——把收尾说明并入 Sources 区块或压缩 Sources 列表（见 §6.7.1 Sources 压缩）。
* **`cols2` / `grid3` 分组几乎不会被切开**：Chrome 会把整个 grid 组推到下一页，所以当该组的**最高卡片**高于当前页剩余高度时，上一页底部会留下大片空白（实测可占整页 40–45%，墨迹覆盖率掉到 4%）。两种处置：
  * 想填满 → 把该组换成**两张全宽堆叠卡片**（各自 `avoid-break`），让第一张先占据当前页剩余空间；
  * 需要并列对照 → **接受留白**。这是"分组不可分"的几何事实，不是 bug——`cols2` 里单张卡若高于整页剩余高度，任何 margin / padding 微调（实测省 4mm 无效）都救不回来。

> **第三种处置：把「章节开头的图表块」主动设计成整页 spread（实测某份报告的 07 增长引擎）**。当某节以一个高图表（`.engine` / `.funnel` / 大图组）开头、其后紧跟 `cols2`，而该 `cols2` 的**最高卡 > 图表块之后的剩余高度**时，图表块所在页必然留下 30%+ 空白。此时反复压 `cols2` 是徒劳（差值动辄 20–40mm），**正解是反过来把图表块做大到接近满页**：加大其内部容器的垂直内距与节点间距（**不是**字号），让它自然占据整页，读者会读成一张有意的整页图解 spread。实测：`.elayer` 内距 7pt→18pt、`.enode` 内距 4pt→10pt、`.econn` 间距 3pt→6pt，引擎块 115mm→188mm，该页内容 173mm→**247mm**（可用高 258mm），页数不变（14 页）。
> * 适用条件：图表块单独占一页时**总高仍 ≤ 258mm**（含节标题 + 图表 + 图注）。上例为 12 + 7 + 188 + 15 ≈ 222mm，留 36mm 安全余量；若逼近 258mm 就会整块跳页，反而制造新的空白页。
> * 判断口诀：**「组底留白救不回来，就把上面那块撑满」**——撑大图表的花费远低于重构分组，且视觉上是加分而非妥协。
* **不要靠"微调几个 pt"去凑分页**：实测给分组减 4mm 内边距对是否换页毫无影响（差额通常在中文字数上，动辄 20–40mm）。要么重构分组，要么接受断页。

## 4. 页眉与页脚

* **页眉**：PDF 内不设逐页页眉条（Chrome 无法按页变化，且会挤占正文）。章节身份由 h2 的编号与 kicker 承担。若确需页眉，用脚本 `--label` 只做页脚左侧标识。
* **页脚（脚本注入，逐页重复）**：
  * 左侧：`rv-footer-label` meta 的值（建议 `品牌 · 报告类型 · YYYY-MM`）
  * 右侧：`第 X 页 / 共 Y 页`
  * 上方 0.5pt 细线（`--border` 色），左右两侧与正文区左右缘对齐（内缩 15mm）
  * 字号 8pt，色 `--muted`
* 页脚与正文之间由下边距（22mm）隔离，正文最底端不得低于距页面底部 22mm。
* 首页（Cover + Executive Summary）**同样带页脚**：页 1/共 N 的连续编号是刻意设计（报告完整性信号），不做"封面无页码"的特殊处理。

## 5. 设计令牌（与 HTML skill 同源 · 打印优化）

模板 `:root` 定义（light 为打印基线；dark 仅屏幕）：

```css
:root{
  --bg:#ffffff; --surface:#f7f7f8; --surface-2:#eef0f3;
  --border:#e4e6eb; --text:#1a1d21; --muted:#5c6470;
  --accent:#4f46e5; --on-accent:#ffffff; --accent-soft:#eef2ff;
  --ok:#15803d; --obs:#1d4ed8; --inf:#b45309; --est:#7e22ce; --unk:#475569;
  --radius:10px;
  --font:"Microsoft YaHei","PingFang SC","Hiragino Sans GB",-apple-system,"Segoe UI",Arial,sans-serif;
  --mono:ui-monospace,Consolas,"Courier New",monospace;
}
```

* **字体必须是本机系统字体**（离线渲染，无 webfont）。中文优先 `Microsoft YaHei`（Windows）/ `PingFang SC`（macOS）。
* 阴影在打印下意义有限，可保留极轻阴影或直接省略；**边框承担主要分层职责**。
* 用 `print-color-adjust:exact` 确保底色与图表色被打印。
* 品牌色只替换 `--accent` / `--accent-soft` / `--on-accent`（必要时加 1–2 辅色），语义色（fact/obs/inf/est/unk）**保持不变**，否则证据分级语义会失真。
* 对比度：正文文字对底色 ≥ 4.5:1；浅色底上不用高饱和品牌色写长文。

## 6. 组件配方（打印版）

骨架、全部 class 与示例都在 `assets/template-a4.html`，本节说明**与网页版的差异**与用法要点。

### 6.1 第 1 页 · Cover + Executive Summary（合并页）

```html
<section class="cover">
  <p class="kicker">DTC GROWTH RESEARCH · 2026-09</p>
  <h1 class="avoid-break">Nike：从批发分销转向 DTC 直营的增长重构</h1>
  <div class="meta-chips">…研究对象 / 研究日期 / 数据截止…</div>
  <p class="lead">核心结论：……<b>关键短语/数字</b>……</p>
  <div class="kpi-grid">…3–4 张 KPI…</div>
  <aside class="takeaway"><h2>关键发现</h2><ol>…3–5 条…</ol></aside>
  <p class="legend">…证据分级图例…</p>
</section>
```

**封面主标题文案铁律（跨介质统一）**：`h1` 固定为 **`品牌名：一句总结性描述`** —— 品牌名在最前 + 中文全角冒号「：」+ 一句陈述式描述（结论 / 定位 / 增长机制），建议 8–28 字；日期与报告类型字样放 `kicker` / meta chips，不进主标题。**同一份报告的 PDF 与 HTML 版主标题必须逐字一致**；用户指定某版为准时以该版为准、另一版回改对齐。

* 整页只讲一件事：**这是关于什么的报告 + 最重要的结论 + 3–5 条关键发现**。
* 首屏（第 1 页）**不要**出现大段连续正文；需要展开的内容放第 2 页起。
* `.lead` 仍是"结论卡片"：浅底 + 左侧 4px accent 竖线 + 右侧圆角；关键短语用 `<b>` 加粗。
* `.kpi-grid` 保持 flex 单行等宽（3–4 张最佳；PDF 正文宽 180mm，超过 4 张会过窄）。

### 6.2 KPI 卡

* 三部分"小标题 / 大数字 / 说明"各自第一行对齐：`.kpi-label` 固定最小高度；`.kpi-value` 只放数字 + 单位（`white-space:nowrap`）；`.kpi-note` 顶部对齐。
* 日期只到"年-月"；评分取确切值不列范围；"约"等修饰词放 note。

### 6.3 Insight / Finding 卡

`.finding` + `.finding-head`（编号 + 标题）+ `.evidence`（每条来源标注）+ `.analysis`（左侧竖线，视觉弱化）。
挂 `.avoid-break`：卡片不与自身拆分；长度超过半个页面时主动拆成两张卡。

### 6.4 Timeline

* 纵向 `.timeline`（左竖线 + 圆点）：适合混在卡片 / 正文里。
* 横向 `.timeline-h`：里程碑独立成块时用；**节点多时自动换行**（`flex-wrap:wrap`），禁止横向滚动。
* 每个 `.timeline li` 挂 `.avoid-break`。
* 纯 CSS 圆点与轴线段，注意 marker 圆心精确落在轴线上（用绝对定位 + 统一 top 值）。

### 6.5 表格

需要**精确逐行对照**才用表格；单维占比 / 排名一律用图表（§7）。配方：

```html
<div class="table-wrap">
  <table>
    <caption>对比矩阵标题（口径与来源）</caption>
    <colgroup><col style="width:34%"><col style="width:20%"><col style="width:20%"><col style="width:26%"></colgroup>
    <thead><tr><th>维度</th><th class="num">指标 A</th><th class="num">指标 B</th><th>来源</th></tr></thead>
    <tbody>
      <tr><td>项目 1</td><td class="num">…</td><td class="num">…</td><td><span class="src-chip">SRC-001</span></td></tr>
    </tbody>
  </table>
</div>
<p class="tbl-cont">表头跨页自动重复；若表格跨页，可在此加"（续）"提示。</p>
```

* `<colgroup>` 显式定列宽（`table-layout:fixed` 已内置），避免长文本把某列撑垮。
* 数值列用 `.num`（右对齐 + `tabular-nums`）；表头浅底 + 小号大写。
* `thead{display:table-header-group}` → 跨页重复表头；`tbody tr{break-inside:avoid}` → 单行不拆。
* 表格**不要**挂整块 `.avoid-break`（长表一定跨页，挂上会整表跳页留下大片空白）；短表（≤8 行）可以挂。
* 禁止 `overflow-x:auto`；窄列内容靠 `overflow-wrap:anywhere` 换行。

### 6.6 Quote 卡

大字号引言 + 左侧 accent 竖线 + 说话者身份与来源。挂 `.avoid-break`。

### 6.7 来源与证据

* 正文数据点旁：`.src-chip`（`SRC-012` 或来源短名，可带链接）。
* 文末 `Sources` 节：**开放区块**（不用 `<details>`），逐条列出 `SRC-ID · 名称 · 类型 · 链接 · access 日期`，`break-inside:avoid` 单条防拆。跨页时重复小标题。
* 证据徽章 `.badge.{fact,obs,inf,est,unk}`：文字 + 颜色双重编码，**颜色不是唯一线索**。
* **图例只出现一次**：第 1 页（或 Cover 页底部）给五行图例；Sources 节可再复述一行（不想重复就只在首页给，正文改注"图例见首页"）。

#### 6.7.1 Sources 压缩（条目多时的标准做法）

实测（29 条来源）：8pt + 长 URL 换行下，29 条约占 1.3 页，会把收尾说明挤成孤尾页。按下列顺序压缩，**全部保留可溯源性**：

1. **access 日期去重为一行全局声明**：条目里 29 次重复的 `· access 2026-09-09` 是纯冗余——删掉逐条后缀，改为节首一行"全部来源的访问日期均为 **2026-09-09**（As of）"。§13 要求的 Access date 信息完整保留。
2. **类型图例做成节首一行**：`First-party 官方 / Platform 平台 / Media 媒体 / Community 社区`，替代逐条解释。
3. **收尾说明合并成一段**：把"数据口径与证据说明"+"数据提示"+"研究日期/作者署名"并成 1 段，别拆成 3–4 个 `<p>`。
4. 仍不够时才降 `font-size:7.5pt` + `line-height:1.20` + `li` 间距 `0.5pt` + 卡内边距 `10pt 14pt`（7.5pt 是 design-system §2 的硬下限，不得再低；**行高与间距不受字号铁律约束，是合规的降高手段**）。
5. 顺带检查：`qc_png/` 目录不清理会遗留旧页 PNG，误判页数——重渲染前先 `rm -rf qc_png`。

**⚠️ 量高必须用真实打印宽度（最容易踩的坑）**：浏览器里量高度时，若视口是 900px（≈238mm），列宽比 A4 打印内容宽度（尺寸计算见下）**宽得多**，文本换行更少 → **高度被低估约 56mm**（同一张 39 条来源卡：900px 视口量到 185mm，真实打印 241mm）。据此定的行高/间距参数必然在渲染时跳页。
* 量高时先 `Emulation.setDeviceMetricsOverride({width: 680, ...})`——**A4 纵向打印内容宽度 = 210 − 左 15 − 右 15 = 180mm ≈ 680px**（本项目 `@page` 边距固定 17mm/15mm/22mm/15mm）。
* 断言：`卡高 + 收尾块高 + 间距 ≤ 258mm`（可用页高 = 297 − 17 − 22）。

**分页机制（关键，实测 33 条与 39 条两种规模）**：多列容器（`columns:2`）与 CSS grid 在 Chrome 打印时**都不倾向于被拆到两页**，而是整块跳到下一页——于是留在上一页的只剩「Sources 小标题 + 前一分节的尾巴」，墨迹覆盖率掉到 ~4%（QC 报"近似空白页"）。因此"把收尾说明并入 Sources"本身**不解决问题**，反而可能让列表连同页脚整块下移。**三种有效修法**：
* **首选：两张普通 `<ol>` 放进 `display:grid;grid-template-columns:1fr 1fr`**（实测 20 + 19 条分栏）。普通列表高度可预测、分栏点确定，**彻底绕开多列容器的整块跳页**；比 `columns:2` 稳。
* **压缩前序分节**（`section` 间距、`.card` 内边距、`.evidence li` 行高/间距），使**前一分节收口于上一页**、Sources 集群能从**新一页顶端整块展开**（实测：14 页带孤尾 → 12 页全填充）。
* **配 `break-before:page`（`page-break-before:always`）**：让整张来源卡**恒定从新一页顶端展开**，标题与列表之间不会被分页切开，孤尾页直接消失；代价只是上一页底部不填满（分节留白，可接受）。
* **组合拳（39 条实测）**：`grid` 双栏 + `break-before:page` + 行高 1.20 + `li` 间距 0.5pt + 字号守 7.5pt → 卡高 212.5mm，**连同收尾块 247.2mm ≤ 258mm，39 条稳定一页装完**。
* ⚠️ **不要给 `.sources` 加 `break-inside:avoid`**：它会让卡在"已有剩余空间"时也整块下移，反而多出一页（实测：加之前卡落在 30mm 处、卡高被拉到 256mm；去掉后正常落在 215mm 内）。
* 备选：改成**单列**（`columns:1`）——单列普通列表可自然跨页，不再整块跳页，但占用更多页高。
* 判断口诀：**"多列列表要占一整页"**——先让它前面的内容别和它抢同一页（`break-before:page` 是最直接的实现），再谈压缩。

## 7. 图表套件（Chart Suite）

> CSS 已全部内置在 `assets/template-a4.html`（打印版，含 c1–c5 色板），不要自造样式。图表示例见页面底部 `<template id="chart-suite-copyme">`。

**默认规则（防退化，强制）**：凡报告中出现 **≥3 条同维度、可比较的定量数据**（占比 / 份额 / 排名 / 粉丝 / 评分 / 价格 / 数量 / 金额 / 时间点），**必须用图表呈现**，不允许退化为纯文字列表或每行一个孤立 KPI。

| 数据形态 | 默认图表 | 内联变量 |
|---|---|---|
| 占比 / 份额 / 排名 / 粉丝 / 评分数值对比 | 水平条形组 `.bars` | `width` = 值 ÷ 组内最大 × 100% |
| 同一指标多档位 / 多时间点（价格阶梯、历年营收） | 垂直柱状 `.vcols` | `--v` = 该值，`--max` = 组内最大 |
| 单一关键占比强调 | 环形 `.donut` | `--p` = 百分比数值，`--col` = 颜色 |
| 层级递减 / 转化结构 | 漏斗 `.funnel` | `--w` = 相对宽度 % |
| 机制 / 因果 / growth_engine | 纵向层流 `.engine` | `.elayer` 分层 + `.econn` 标关系 |
| 里程碑 / 时间顺序 | `.timeline` / `.timeline-h` | — |
| 多列精确交叉对照 | 表格 | 唯一"表格优先"场景 |

**铁律**

* 每个数据点**原样显示真实数值文本**；柱长仅作比例示意。
* 每组图下方一行 `.chart-note`：`柱长按数值比例示意` + 证据徽章 + `SRC-NN`。
* 数值 / 单位 / 口径零改动；ESTIMATE 徽章必须保留在 chart-note 或数据点旁。
* 图 + 图注 + note 三者共同挂 `.avoid-break`（用一个包裹容器），**否则图会被分页切开**。
* 量级差异过大（如 $3.3B vs $27M）不强排同图，改表格并列两口径并注明"不等轴"。
* 图表字号：数值 ≥8pt，轴 / 标签 ≥7.5pt；不放大会导致不可读时，改用表格。
* 打印环境下 `conic-gradient`（donut）与 CSS 渐变均可正常输出；不要用 SVG 滤镜 / 混合模式。

## 8. 信息设计原则（内容 → 视觉映射）

| 内容类型 | 首选表达 | 何时不用 |
|---|---|---|
| 单个最重要数字 | KPI 卡 | 数字没有独立意义时并入叙述 |
| 3–5 条关键结论 | `.takeaway` / Finding 卡 | — |
| ≥3 条可比较定量数据 | 图表（§7） | 只有 1–2 个对象；口径不可比 |
| 随时间变化 | Timeline | 无时间顺序 |
| 转化 / 分层路径 | Funnel | 无漏斗逻辑且数据不足 |
| 机制 / 因果 | 层流图 / 关系图 | 线性列表更清晰时 |
| 一组对象（产品线 / 社媒账号 / 用户群） | 卡片网格 | 需精确对照 → 表格 |
| 原话 / 官方口径 | Quote 卡 | 可正常转述时 |
| 大量原始细节 | 来源节 / 附录 | — |

判断标准始终是：**这个组件是否让读者更快理解？** 不为凑数强塞。

**独立站流量来源（Acquisition 节 · 强制 · 分口径呈现）**

* **不得只放一个「自然搜索占比」环形/单值。**
* **① 主口径 = 最新的一手平台数据**（分析依据）——**平台公开几项就呈现几项**：数据充足时用三张并列 KPI 卡 + 完整渠道表；只公开 1–2 个维度时就只放这 1–2 项，**不为凑「Top 3」补位**。
* **② 参照口径 = 较早或二手转述**（如有）——**全部并列列出**（不得因看似矛盾而删除），标"仅作参照，不作为分析依据"，视觉弱化。
* 每条给齐：排名 + 渠道名（中英）+ 占比 + 规模 + 环比 + 数据月 + SRC；派生值注明"派生值"。
* 两口径差值写明"跨平台不可相加或互比"，但**只作方法论注释**——**不得进首页「关键发现」、不得写进痛点/优势区块**。
* 未公开项标 **UNKNOWN**（不反推）；极小值（≈1%）用数值卡，不画近零长度的条。首名若有品牌词/非品牌词拆分，一并呈现并注明来自哪个口径。

## 9. 首页与章节页版式

* **第 1 页**：见 §6.1。视觉重心 = 主标题 + `.lead` + `.takeaway`，三者占据首屏主体。
* **章节**：`h2` 用"编号 + 标题"（`03 · 获客与增长`），左对齐；可选 4pt accent 短条做视觉锚点（宽 28mm，不加整行色块）。
* **跨页的大章节**：不要每章强制新起一页；仅在章节确实切换主题且当前页剩余空间 < 1/3 时才 `.page-break`。
* **收尾页**：Sources 节 + 页脚版权行（`© {year} {Author}`，作者来自 `rv-author`，未提供则省略该行）。

## 10. 质量红线

* 页面尺寸、边距、页码、页脚四者一致且逐页成立。
* 无内容越过页边距（横向溢出、纵向顶到页脚）。
* 无近似空白页（墨迹覆盖率 < 3%）与过满页（> 92%）。
* 卡片 / 图表 / 表格行 / 时间线节点不被分页切开；标题不孤悬页底。
* 数值、单位、口径与 Markdown 完全一致；证据分级与来源完整。
* 无 Part 3 与任何内部操作信息。
* 正文 ≥10pt，页脚 ≥8pt，无不可读字号。
* 与 HTML 版共用同一套色彩、字体层级、卡片与图表语言。
