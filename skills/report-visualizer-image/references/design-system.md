# Report Visualizer — Image 设计系统参考

本文件是图片版可视化产物的设计与排版权威来源。生成任何一张图前阅读本文件相关章节；与 `assets/report-canvas.css` 配合使用（CSS 只实现，决策在本文件）。

## §1 画布与解剖

### 1.1 画布
- 每张图 = 一块 **1600×1200 逻辑像素**（**4:3**，适配主流社媒信息图）画布，渲染时 deviceScaleFactor=2 → **3200×2400 px PNG**。禁止滚动/溢出，所有内容必须适配 1600 宽、1200 高。
- 水平安全边距 72px；卡片间距 20–24px；画布内层网格 12 列体系（不需要严格实现，视觉节奏参考即可）。
- 画布底色默认浅色（white）；如需深色底整套统一，不允许一套里深浅混用。

### 1.2 统一解剖结构（每张图都含）
```
┌──────────────────────────────────────────────────┐
│ 页眉带  y≈40–190    kicker · 大标题 · 副题  数据日期chip │
│ 正文区  y≈200–1110  副题下缘 → 页脚上缘，本图的主信息（≥70% 高）│
│ 页脚带  y≈1120–1200 图号与名称 · 口径 · SRC · 署名 · 证据分级图例 │
└──────────────────────────────────────────────────┘
```
- **页眉带**：kicker（左，小号，EN 标签在前 + 页号在后 muted，如 "BRAND SNAPSHOT · 01 / 09"）+ 顶部右侧数据截止 chip（"数据截至 2026-09"）；标题行左侧放 8px×34px **主色竖条（与主标题同色）**；**主标题 = 4–16 字、品牌主色、≤ 2 行**（标题系统规范见 §3）；副题 = 小号浅色（≤ 80 字符），承载结论/上下文，不与主标题竞争。
- **正文区（核心）**：在 1600×1200 画布内指**副题下缘 → 页脚上缘**之间的区域，承载这张图的主故事。占版规则、居中与文本对齐见 §1.3、§1.6。每张图只讲一个主故事。若有两个并列故事，用清晰分区条（章节标签）分隔。
- **页脚带**：上边框 1px 主色 10% 分隔线；左：`01 · Brand Snapshot`；中：口径一句话（只讲数据口径，不出现"出自某报告 / 第几章 / 工具名"等自指）；右：本图用到的 SRC 短 chips（≤4 个，多则省略并在来源总览页说明），chips 末尾接**作者署名** `© {year} {Author}`（默认 `Yan`）。**证据分级图例行**（FACT/OBSERVATION/INFERENCE/ESTIMATE/UNKNOWN 徽章 + 一句话含义）在每一页页脚常驻。

### 1.3 正文区占版与居中（content-area fit & centering）

正文区是版面的主舞台，**内容应撑满正文区高度的 70%–80%，上下对称留白（约各 10%–15%）；块间空隙尽量小；块内文字上下居中于容器**。**禁止**依赖大段空白撑版或缩字号硬塞。

```
┌─ 画布 1600×1200 ───────────────────────────────────┐
│ 页眉带                                              │
│ ╭ 正文区 (≈ y 200–1110) ╮  ← 副题下缘 → 页脚上缘 │
│ │ ▒▒▒▒▒▒  ≈ 10–15% 上下居中  ▒▒▒▒▒▒ │  ← 内容整体占 70–80%；首尾对称留白 │
│ │ ████ 主内容块（高度 = 正文区 × 0.7–0.8）████ │
│ │ ▒▒▒▒▒▒  同样 ≈ 10–15%             ▒▒▒▒▒▒ │
│ ╰─────────────────────────────────────────╯ │
│ 页脚带                                              │
└─────────────────────────────────────────┘
```

具体落地：
- **结构**：`.content{justify-content:center; gap:小}`，内容整体在 `.content` 内居中；不要 `space-evenly` 让块被边缘强制拉到上下，导致首尾空隙大且易撞页脚。
- **占版比**：**内容整体高度 = 正文区高度 × 70%–80%**（推荐 74%–78%）。交付前用 `_geo.cjs` 或等价探针验证：`fillPct ∈ [70, 80]`，`topGap ≈ botGap`（`centerDelta` 接近 0），`over=[]`。Probe 已在 `report-visualizer-image/scripts/_geo.cjs` 提供。
- **块间空隙尽量小**：直接子级之间的 `gap` 与相邻 `margin-top` 取页面需要的最紧值（典型 8–18px），不要用 "大块之间 space-evenly 均分空隙" 撑版。
- **块内文字上下居中**：每个内容容器（`.card`、`.kbig .cell`、`.identity .ic`、`.vcol2` 等）以 `display:flex;flex-direction:column;justify-content:center` 把内文居中；自然高度容器同样把内文放容器垂直中线，不要让大行内部顶端堆字、底部留白。
- **行间均布例外**：仅当正文区总内容天然高度 < 正文区 × 0.7（如唯一单块卡片页，如来源总览），可让该块 `flex:1` 撑满正文区、内部再按空间均布；块内文字仍按上述 "上下居中" 对齐。
- **不要做的事**：① 用 `space-evenly` 让块撞页脚 / 撞顶；② 用 `flex-start` 把内容堆在顶部、底部一整条空带；③ 内容自然已 > 正文区 × 0.85 时还硬塞，会把内容推进页脚带（`over` 出现负 gap 即视作越界）；④ 缩字号以让短内容"看上去贴页脚"——应补足信息层或在 §1.3 限度内调整行距/行高。
- **网格静默截断陷阱（2026-09 沉淀 · 来源总览/高密度网格页必看）**：CSS Grid 上写了**显式 `height` + `grid-auto-rows:1fr`（或固定行高）**，再给子项加 `overflow:hidden` 时，若某行内容略高于分到的行高，**末行文字会被静默裁掉且不报错**——`_geo.cjs` 的 `over`（页面级越界）**查不出来**，只有目检 PNG 才发现（典型：来源总览页的 URL 整行消失）。规则：**高密度网格页一律用「自适应行高（不写固定 height / autos） + 不写 overflow:hidden」**，总高靠**列数**调节（3 列装不下的 29 条来源改用 4 列），而不是压缩行高或裁内容；能用列数解决就不要动字号（**例外**：来源总览页有 2 页硬上限，见 §1.4——该页允许在字号下限内下探，但仍不得用固定行高或 `overflow:hidden`）。
- **`.content` 溢出陷阱（2026-09 沉淀）**：当正文区总内容高度 > `.content` 高度（如诊断页 4 张 tcard + sectag 合计 1076 CSS px 而容器仅 864），`justify-content:center` 会把溢出**对称分布到上下两端**，导致首子元素向上溢出覆盖 `.head` 标题。**修复优先级**：① 先压缩内容（缩小字号 / 缩短文案 / 改 2×2 grid）；② 不要把内容推到 `>0.9` 边缘；③ `.cols2` / `.row` 中避免 `align-items:stretch` 双列等高（一张 tcard 内容特长会拉高另一列）。`_geo.cjs` 在 Windows 含空格路径下可能返回 null metrics，必要时改用 Playwright `bounding_box` 实测关键元素 `.head / .h1 / .sub / .content / .cols2 / .tcard` 位置确认布局。
- **fillPct 微调技法（2026-09 沉淀 · 只超一点点时怎么收）**：当 `fillPct` 只比 80 高出 0.3–2（如 80.2 / 81.4）时，**先判断撑高的是哪一类元素**再动手，否则会白改一轮：
  - **自由高度容器**（`.node` / `.loopcard` / 竖排 `.card` 等）——缩 `padding`（垂直向）或 `gap` 最有效，通常 3–4px/行即可收 ~1.5%。
  - **网格等高容器**（`.cols2` / `.ccards` 里的 `.card`）——其高度由**该行最高兄弟**决定，**缩内部的条形高度 / 子元素字号完全无效**（本轮 05 页缩 `.brow .bf` 18→16px 只降了 0.5%）；必须缩**卡片自身 `padding`**（`.card{padding:20px 24px}` → `12px 20px` 一步可收 ~2%）或压缩**主导高度的那段文本块**（通常是页内最长的 `.bnote` / `.cd`）。
  - 每次只改 1–2 处后重跑探针，不要一次大改（易从超 80 直接掉到 70 以下、又得回调）。

### 1.4 远读与密度规则（v2 · 依使用反馈沉淀）

图片最终常以 ≤ 画布宽度 50% 展示（PPT / 社媒 / 图库缩略），因此**逻辑画布上的字号必须按"远读"设计**，宁大勿小：

| 元素 | 最低字号（1600 宽逻辑 px） |
|---|---|
| 显示数字 / KPI 主值 | 46–52（条形图数值行 ≥17） |
| 大标题 h1 | 50–56 |
| 区块标签 / sec / 条形 label | 17–19 |
| 正文 / 卡片说明 | 15–17（禁止 ≤12 的正文） |
| 图例 / 卡片 meta | 12.5–14 |
| 微注 / chart-note / 页脚口径 | 11–12.5 |
| 来源 URL（仅来源总览页，**v3 起为必附**） | ≥9.5，等宽字可折行 |

- **每页 4–5 个信息层（v3 · 默认标准）**：一页由「数据层 + 主视觉层 + 解读层 + 补充证据层」堆叠（如 KPI 行 + 主图表/流程 + 解读卡 + 附注/口径），**解读层为必含项**——把数据翻译成一句结论，而不是只摆数字。层数不足时优先从报告其它已研究章节补同源组件（零新增数据），避免"一图只有一块"造成的空洞感；若某层内容单薄，把该层内容并入相邻层或以大字化填充，**不要靠加空白撑版**（与 §1.3 内容占版规则一致）。
- **横向时间线**：节点 ≤8 个；节点标题 ≥15px、说明 ≥12px、圆点 ≥13px；单行空间不足就把上下说明改成两行，不许压缩到不可读。
- **战役/长文本卡片**：卡片多于 2 张时优先竖向堆叠大字号（而非横排挤小字）。
- **信息不足的页**：允许从报告其它已研究章节抽取**同一报告内**的可支撑组件补版（如产品矩阵表、信任条款 chips），仍零新增数据。
- **来源总览页（硬约束：全集合计 ≤ 2 页）**：每条 SRC 三层结构"短名 + 类型 tag + 完整 URL"，URL 等宽小字折行、不截断，**逐条可复制**（只写来源名而不给 URL → 视为不合格，URL 是"可验证"的落点）。仅此页允许高密度。**来源总览页总数上限为 2 页**（2026-09-17 用户指定，**取代**此前"≥30 条可拆多页"）——无论登记表多少条，都必须在 2 页内装完；装不下时按下方「并页配方」**下调字号 / 并辅助块 / 增列数**压回 2 页，**不得加第 3 页**。
- **来源总览页 · 两页并页配方（2026-09-17 用户规则后的标准做法，62 条实测）**：目标固定为**恰好 2 页**，按登记表条数选档，**先算 URL 长度分布再定列数与字号**（决定行高的是 URL 折行行数，不是条数）：

  | 档位 | 来源条数 | 列数 | 短名 / URL / tag | 单页条数 | 行数 |
  |---|---|---|---|---|---|
  | 舒适 | ≤42 | 4 | 14.5 / 11.5 / 10.5 | ~21 | 6 |
  | 紧凑 | 43–62 | **5** | 13 / **10.0** / 9.5 | ~31 | 7 |

  关键取舍：**列数从 4 提到 5 会把 31 条的行数由 8 行压到 7 行（省一整行 ≈ 80px），这是 2 页装得下的前提**；代价是卡变窄、URL 折行变多，因此必须同步下调字号。**字号下限**：短名 ≥12.5px、URL ≥9.5px、tag ≥9px——已到下限仍装不下时，压缩方向转为**内容侧**（合并辅助块、精简口径文案、把类型分布条并入辅助条），或在交付说明中声明"来源页 2 页为上限，完整清单见登记表侧车文件"，**不得再降字号、也不得加页**。单条仍为三层 `chip 行 + 短名 + 完整 URL`，网格一律**自适应行高**（禁固定 `height`、禁 `overflow:hidden`，避开静默截断陷阱），占版靠**逐页 `.sg{gap}` / `.se{padding}` 微调**收敛，不靠全局缩放。实测 62 条拆 31 / 31，两页 `fillPct` = 75.4 / 77.1。
- **来源页再压缩（2026-09 沉淀 · 用户要求减少来源页数时）**：若要在**更少页**里装完（如 40 条从 3 页压到 2 页），**优先增加列数而非删条目**——`grid-template-columns` 3 列 → 4 列可让 20 条从 7 行降到 5 行；同时把 URL 字号 12→11px、短名 15→14px、`srow` padding 8px→7px、`gap` 12/14→11/13，即可单页容纳 20 条且 `fillPct` 落回 71–76%。**URL 必须保持完整可折行**（`word-break:break-all`、不设固定行高 / `overflow:hidden`，避开静默截断陷阱）；短名过长时用 `text-overflow:ellipsis` 省略无妨。压缩后务必逐张目检 URL 是否被裁。**与 2 页上限的关系**：4 列 × 20 条/页 是「来源 ≤42 条」档的合规解；条数超过 42 时改走上一段的 5 列紧凑档，不要沿用 4 列硬塞。
- **来源页 URL 完整性机器自检（2026-09 沉淀 · 无头环境必跑）**：§6 只要求「逐张目检 URL 是否被裁」，但无头环境**看不了图**，静默截断（`overflow:hidden` 吞掉尾部）不会被 `_geo.cjs` 的 `over` 捕获——因为元素并没有越出画布。改用 `scripts/_urlcheck.cjs`：逐条读取来源卡（约定容器 `.se`、子元素 `.sr .src` / `.nm` / `.ur`）的 **SRC-ID / 短名 / URL 文本**，与 Source Registry**逐字比对**，并同时断言 `scrollHeight ≤ clientHeight + 1`（无视觉裁切）。用法：`node _urlcheck.cjs <chrome.exe> <html 绝对路径…> --registry <sources.md|registry.json>`。**`--registry` 必传**——不传时脚本只验「无裁切」，**不会**验文本逐字一致，此时输出里 `textOk` 为 `SKIPPED` 并打印提示（2026-09 沉淀：早期脚本只查裁切、却在文档里声称输出 `TEXT_OK`，属"文档承诺 > 脚本实现"，静默给出偏强的结论）。Registry 两种形态都认：markdown 侧车表（`- **SRC-001** 名称 — First-party — https://… · access 2026-09-17`）或 JSON（数组内含 `id`/`src_id` 与 `url` 字段）。**通过线**：各页 `textOk` 全为 `true`、`urlMismatch=[]`、`urlClipped=[]`，且末行汇总 `pass: true`（`unusedInPages=[]`，即 Registry 无未落地条目）。**短名的 `ellipsis` 截断不算失败**（PNG 介质下 `title` 不可见，短名只作标签、URL 才是可验证落点），脚本会把 `nmClipped` 单列出来供人工判断。
- **来源页行高对齐：URL 预留 2 行（2026-09 沉淀）**：同一套卡片样式下，**页面密度会随 URL 长度漂移**——官方站与平台页的短链多为 1 行，新闻/媒体页的长链普遍 2 行，实测行高差 18.5px（6 行差 111px），导致同批来源页一个 70.1%、一个 77.9%。**解法：给 `.ur` 加 `min-height:2.60em`（= 2 × `line-height:1.30`）**，让短链页与长链页行高一致。注意这只是**预留下限**：URL 超长仍会折到 3–4 行并把该行撑高（62 条里最长一条 187 字符、折 4 行；31 条/页 时约 5 条折 3 行），因此**不要**用固定 `height`（会静默裁切）。预留、并采用 5 列紧凑档后两页仍落在 75.4 / 77.1%。
- **来源页逐页栅格微调（2026-09 沉淀）**：URL 行数分布天然不均匀，**只靠单一字号无法让两页同时落入 70–80%**。做法是**类型尺度两页完全一致**（短名 13px / URL 等宽 10px / tag 9.5px 不随页变），只把 `.sg{gap}` 与 `.se{padding}` 做成逐页常量（62 条 2 页档实测：15 页 `gap:8px;padding:5px 10px`、16 页 `gap:6px;padding:4px 10px`，对应 75.4% / 77.1%）——间距差异在分页独立的图片间不可察觉，而字号差异会看得出来。⚠️ 判据是**该页的行数与 URL 行数分布**，不要盲目给所有页同一套压缩参数。
- **来源页辅助条：恒定 4 格 + 2 页上限下只放两条（2026-09 沉淀）**：2 页配额下辅助块预算只够两格位置，分配为——**首页**放「来源类型分布条」（4 格，每格 = 类型 + 条数 + **该类型的使用边界**，把原独立的"类型使用边界卡"并进来）；**末页**放「口径说明条」（4 格 = 本页条数 / 类型构成 / 一手来源 / 口径提示）。口径条**必须恒定 4 格**，类型多于 2 类时把各类型计数**合并成单格「类型构成（N 类）」**，否则 `cells[:4]` 会把「口径提示」整格挤掉——**静默丢信息**（实测命中：3 类构成时口径提示消失）。容器类名前缀用脚本自有名（如 `.aux` / `.ax`），**禁复用 `.legend`**——该名归页头证据图例所有，同权重后定义会破坏其布局；生成脚本里加断言：辅助条内格子恰好 4 个、且口径提示文案确实出现在页面中。
- **作者署名（默认必有，勿省略）**：**每一张图**页脚右端 SRC chips 之后放 `© {year} {Author}`，样式 `.foot .fby`（11.5px 粗体、`b` 加深、`margin-left:8px`，紧接 SRC chips）。作者默认 `Yan`；仅当用户明确提供其他署名/不署名要求时才改变或省略。画廊 index.html 同步：每张卡片说明区加同一署名行（如 `© 2026 Yan · SRC-xxx`），页尾版权声明带 `© {year} {Author}`。该署名是"作者归属"，与"去自指"（不出现报告名/章节/工具名）不冲突。

### 1.5 页眉页脚字号规格（当前生产标准）

页眉与页脚为独立两套字号体系（与正文分开），按"区段缩放"基准实施：

| 区段 | 缩放因子（相对基线） | 当前生产常用值 |
|---|---|---|
| 页眉带（页码/kicker/标题/副题/chip） | × 26/19 ≈ 1.368 | kicker 17.8 · datechip 16.4 · h1 71.2 · sub 26.0 |
| 页脚带（fid/fmemo/fby/fsrcs/flegend） | × (26/19) × 1.2 ≈ 1.642 | fid 21.4 · fid small 18.1 · fmemo/fby 18.8 · fsrcs.src 18.1 · flegend 17.3 · flegend.ev 15.6 |
| 正文主类（barset/sec/KPI/tl/flow/quote/chip 等） | × ≈ 1.52 | ev 16.0 · src 16.8 · sec.t 29.0 · kpi.num 85.3 · kpi.lbl 22.8 · brow.bl/bv 22.8/24.4 · tl.tm.d/t/s 22.8/21.3/18.3 · flow.fnode.t/s 29.0/20.5 · quote p 32.0 |

**落地规则**：
- 套用上述缩放时只调整字体大小（不要同步改 padding/gap，否则版面纵向失控）；padding/gap 走正文区自身规则（§1.3）。
- 调整单页时如需让 cols4 KPI 卡的主数字与正文主数字（≈67px）保持视觉尺度，可在该页 `<style>` 中覆写 `.kpi .num{font-size: 60–67px}` 与 `.kpi .num .u{font-size: 27–29px}`。
- 页脚 `border-top` 颜色：`color-mix(in srgb, var(--c1) 14%, transparent)`（品牌主色 14% 透明），与全系列主色保持一致。

### 1.6 收尾规则（交付前必过）
- 交付前用 `_geo.cjs` 量 `bodyH`、`fillPct`、`topGap/botGap`、`over`；通过线：`fillPct ∈ [70,80]`，`centerDelta ≈ 0`，`over=[]`。
- 直接子级 `blockGaps` 在 8–18px 区间；仅当页面需要明显节奏（如流程图箭头、卡片间分隔），可局部 24px。
- 不要为了让短内容"贴近页脚"而缩字号或加白条；按 §1.3 内容占版规则自然落在 70%–80% 即可。

### 1.7 信息密度标准（v3 · 2026-09 基准，后续报告默认对齐）

一份 14 张的图集被用户确认为"内容丰富度达标"的基准。**后续每一份报告默认按此标准产出**，不再回落到"4–8 张轻量集"；除非输入内容确实单薄（此时仍需 ≥8 张，并把每页信息层做满）。

**规模**
- 默认 **12–16 张**（4:3）。页数由报告的信息量决定，而不是由"最小集合"决定——报告有料就铺开，不要压成 8 张以内。
- 允许把弱主题合并，但**不得**用空白页、装饰元素或重复内容凑页数。

**逐页结构（每页 4–5 层）**
1. **数据层**：一组可比定量（KPI 行 / 条形组 / 分段条），每条带真实数值 + SRC chip + 证据 chip。
2. **主视觉层**：该页的图解主体（流程 / 时间线 / 阶梯 / 矩阵 / 对照列 / 双栏）。
3. **解读层（必含）**：把上面两层翻译成一句结论的卡片或引语块——这是 V1 缺失、V2 补齐的关键层，不能省。
4. **补充证据层**：口径说明、附注、规则条款、对比小表、评分/实据条。
5. **（可选）反方/风险层**：与主结论相反的证据或注意事项。

**必含页清单（报告有相应内容时必须出页，没有则跳过）**
- 01 Brand Snapshot — **首图，主标题必须含品牌名**（见 §3.10）
- 口径 / 数字冲突对照页 — 报告存在互斥估算（营收、利润率、估值、拆分比例等）时必出：并列两版数字 + 各自出处 + 解读卡
- 产品与价格体系（价格阶梯 + 品类矩阵）
- 增长引擎 / 增长机制
- 留存机制（会员 / 官方服务 / 配件 / 生态 / 软件 / 社区）
- 获客结构（渠道占比 + 流量趋势）—— **独立站流量来源页按「主口径 / 参照口径」两级呈现**：主口径 = **最新的一手平台数据，平台公开几项就呈现几项**（数据充足时给排名前 3 的全部数据：排名 + 渠道名 + 占比 + 规模 + 环比；只公开 1–2 项时就只放这 1–2 项，**不为凑 Top 3 补位**）；参照口径 = 较早/二手转述，全部并列但标注"仅作参照"。不得只放一个「自然搜索占比」环形；两口径差值写明"跨平台不可相加或互比"，但**只作方法论注释，不得进关键发现/痛点**；未公开项标 UNKNOWN；付费搜索等极小值（≈1%）用数值卡而非近零长度的条。
- 创作者 / 社媒 / UGC 生态（创作者规模 + 分层 + 计佣规则 + UGC 计划）
- 用户画像与使用场景
- 口碑双面（正向 vs 负向两栏并列）
- 竞争格局（分赛道份额 + 竞品卡，标注不可跨赛道比较）
- Campaign 节奏（时间线 + 战役卡）
- 优劣势与机会（S/P/O + 机会优先级）
- 来源总览 — **每条必须附完整 URL**，**全集合计 ≤ 2 页**（见 §1.4）

**密度反模式（禁止）**：一页只放一块内容 + 大片留白；只摆 KPI 不解读；把解读塞进页脚口径行；用图标墙/色块等装饰凑版面；把两页能讲清的内容硬合成一页。

**落地提示（v3 2026-09-12 实测）**
- 按 4–5 层铺满后，**首轮渲染多页会超 80%**（实测 14 页里 7 页 81%–91%）。这不是布局失败，而是密度标准自带的"偏胖"倾向——首轮即应按 §1.6 跑 `_geo.cjs`，对超标页**只用页内 `<style>` 覆写**（压卡片 padding → 15–19px、KPI 数字 → 44–48px、条形高度 → 24–28px、gap → 6–10px、注脚字号 → 14.5–15px），**不要改 `_sys.css`**（会污染全页）。通常一轮覆写即可全部落区间。
- 反向情况（如口径对照表这类"内容偏少但必须出页"的页）会**低于 70%**：优先放大表格字号/行内 padding 提密度，不要用空白硬撑；提密度时容易过冲，回调 padding 比回调字号更平滑。
- **来源页页数（硬上限 2 页）**：§1.4 的"≤ 2 页"是硬规则（2026-09-17 用户指定，取代旧"≥30 条可拆多页"）。条数少（<30）时保持单页，但必须用「来源类型分布条 + 口径注 + 4 列网格」把内容区填满，不得留大片空白；条数多时按 §1.4 的档位表选列数与字号，**压回 2 页**（≥43 条走 5 列紧凑档；>62 条在字号下限内继续并块，并在交付说明里声明完整清单见登记表侧车文件）。

### 1.8 3:4 竖版画布配方（v1 · CCEBC 展会图集 2026-09-16 沉淀）

用于「3:4 竖版 / 每页一个发现 / 用大数字说话」这类社媒海报场景（配合 §5.1 的 `{ratio}=3x4`）。**只覆写画布尺寸与字号，组件结构沿用基础样式**——在 `_sys.css` 末尾追加覆写块，不改组件结构。

**画布**：1200×1600 逻辑 px，@2x → 2400×3200 PNG。截图 `--width 1200 --height 1600 --scale 2`。探针 `_geo.cjs` 已改为**从 `.canvas` 实测宽高**（原硬编码 1600×1200，量竖版会全页误报越界），可直接用，无需另写副本。

**基线参数（实测可用，可直接抄）**

| 元素 | 值 |
|---|---|
| 左右 padding | 64px（`.head` / `.content` / `.foot` 同步） |
| `.content` | `justify-content:center; gap:20px` |
| kicker / datechip | 17px / 14.5px |
| h1 | 62px（≤2 行）· 副题 23px |
| hero 主数字 | 按字符数选：1 字 272 · 2 字 216–224 · 3–4 字 200–216 · 5 字 210；单位 `.hu` 取主数字 ×0.35 |
| KPI 卡数字 | 88px（`.u` 34px，卡内宽窄时 88 是安全上限：`4–20%` 已接近 297px 内宽） |
| KPI 卡 | `padding:30–38px 26px` · `lbl` 22px · `sub` 16px |
| 解读层 `.readout` | 文字 24px · `padding:30px` · `rtag` 胶囊 15px |
| `.foot` | 改 `flex-direction:column`：`.frow`（fid / fmemo / fsrcs / fby 横排）+ `.flegend`（证据图例）两行 |

**占版标定**：`fillPct` 目标 **74%–75%**（区间仍为 70–80）。竖版比 4:3 更线性：**每 +10px 卡片 padding ≈ +0.4pp**。实测 5 页收在 74.0%–74.9%，`centerDelta=0`、`over=[]`。

**单页结构（「1 个发现 1 页」型，共 5 块）**：hero（超大数字 + 标签 + 证据/SRC chip + 一行附注）→ `sec` 区块标签 → `cols3` 支撑 KPI → `readout` 解读卡 → 溯源注（虚线顶边、warn 色小字，如「数据来源：嘉宾现场分享 + AI 语音识别整理，可能有误」）。页数由用户要求决定（3–5 张亦合规），不套用 §1.7 的 12–16 张默认。

**中文折行硬约束**：1200 宽竖版单卡内宽约 **293px**，22px 字号下 ≈ **13 个中文字**。超出 1–2 字就会产生「孤立字」换行（末行只剩 1–2 字）。**只能靠缩短标签或手工 `<br>` 解决，不得缩字号**（§2.3），交付前逐张目检折行——`_geo.cjs` 抓不到这类问题。

## §2 版面规划与几何（Layout Planning & Geometry）

**排版铁律：每张图必须先当作一幅完整构图来规划，然后才允许落单个元素。** 禁止不经过整体规划就把文字、卡片、图表各自独立摆放。所有元素按以下层级自顶向下设计：

```
Canvas（画布 1600×1200）
→ Safe Area（安全区：左右 72px 内边距）
→ Grid（显式底层网格：共同左缘 / 右缘 / 列 / 节奏）
→ Major Content Areas（主内容区划分：一页一个主故事 + 支撑层）
→ Components（组件：尺寸由内容量决定）
→ Typography（文字层级：可读、不重叠）
→ Labels / Sources（标签与来源，最后落位）
```

### 2.1 内容分配（Content Allocation）
- 按信息重要性分配版面：**主视觉应占据内容区的大部分面积**。
- 避免"主内容只占中间一小块、四周大片未用留白"的构图。
- **不要为填空而添加装饰元素**（图标/色块/线条凑数一律禁止）。
- 内容撑不满时按以下顺序处理：① 放大重要组件 → ② 增大图表/图示比例 → ③ 增加**有意义的**间距（不是均分空白） → ④ 简化布局 → ⑤ 重排网格。空着也不行、装饰也不行。

### 2.2 显式网格（Grid）
- 每页必须有隐式/显式的统一底层网格；主要元素对齐到**共同左缘、共同右缘、共同列、共同水平节奏**（间距系统 12–20px 步进）。
- 禁止任意定位（绝对定位、肉眼凑边距、逐项手调 px）。
- 落地方式：优先用 CSS 网格/弹性类（`.cols2/.cols3/.cols4/.row/.grow`）让同层元素共享布局容器，而不是各自量坐标。列数选择必须与内容结构匹配（不要用 4 列硬塞 3 项再留空列）。

### 2.3 组件尺寸由内容量决定（Component Size）
- **组件尺寸由内容决定**，禁止"小组件里塞大段文字"。
- 内容放不下时按顺序处理：① 精简文字 → ② 删除冗余信息 → ③ 放大组件 → ④ 重构网格 → ⑤ 拆分到第二层/第二张图。
- **禁止只缩小字号来硬塞**（见 §1.4 最低字号表）。

### 2.4 文字与排版（Typography）
- 字号必须有清晰层级（h1 → sec/区块 → 正文 → 微注），按 §1.4 与 §5 字号表执行。
- 文字放不下/太小：**不要直接放大字号**，按 2.3 的顺序处理（精简 → 删冗余 → 扩大可用文字区 → 放大组件 → 重排布局），最后才微调字号。
- 任何文字不得与另一元素重叠；文字溢出、裁切都视为布局错误。

### 2.5 对齐（Alignment）
同一系统中的元素必须共享**同一条对齐规则**，而不是各自近似对齐：
- KPI 卡 → 等高、同基线（同容器拉伸 + 统一内边距/字号）；
- 流程节点 → 共同轴线、等距；
- 时间线 marker → 共同轴线位置（见 2.7）；
- 对比列 / 对照表 → 共同网格列；
- 区块标题 / sec → 共同左缘；
- 标签、来源 chip、徽章 → 与所在块统一对齐规则。

### 2.6 几何硬约束（Geometry Constraints）
对含**轴、时间线、流向、关系**的图示，几何关系是**硬约束**：
- 文字描述为"在时间线上"的元素，其**几何中心必须真的落在时间线**上；禁止"视觉上差不多"。
- 同一轴上的多个 marker，必须共享**同一个轴坐标**（同一 y/同一 x）。
- 关系线/箭头必须真正指向其指向的对象边缘/中心，不近似。
- 无法保证精确对齐时，用 CSS 结构保证（flex/grid/同容器/transform:translate(-50%) 居中），不要手工估 px。

### 2.7 时间线规则（Timeline Rules）
1. 先画横向时间线（轴线元素），并确定其精确纵向位置（固定 y）。
2. 每个事件 marker 锚定到该 y：marker 的**几何中心落在轴线**上（常见做法：marker 定位于轴容器内、`top` 由容器统一约束或用 transform 精确居中）。
3. 事件说明/标签**独立**置于轴线上方或下方，不受 marker 位置牵连；上下可交替排版防重叠。
4. 事件 marker 不得偏离时间线（不允许 marker 浮动到轴外、标签挤动 marker）。

### 2.8 溢出预防（Overflow Prevention）
定稿前对每个组件检查：文字溢出、被裁切、相互重叠、内边距不足、与图标/图表碰撞、与相邻组件碰撞。
- 一旦溢出：**先重构布局（放大/重排/精简/拆分），最后才动字号**——禁止用缩字号掩盖结构问题。
- **类名冲突排查（2026-09 沉淀）**：每图的页面级 `<style>` 在本文件内，若为某组件起的类名与 `_sys.css` 的**证据徽章修饰类**重名（`fact` / `obs` / `inf` / `est` / `unk`）或与 `.src` 重名，页面级规则会覆盖 `_sys.css` 的 `.ev{display:inline-block}`，导致 `class="ev unk"` 的徽章被当作块级元素**撑满整行**（典型症状：页脚 legend 的徽章正常，但正文里的某一档徽章突然独占一行、宽度等于所在区块宽）。**规则**：页面自定义类名一律避开上述保留名——"不可得数据"虚线框请命名 `.unkbox` / `.unknote`。出现"某个徽章异常变宽"时，先跑 `grep -n '^\.\(fact\|obs\|inf\|est\|unk\)\s*{' src_html/*.html` 定位冲突。

### 2.9 留白（Whitespace）
留白必须**有意**。可接受的留白：主要区块之间、重要视觉元素周围、外层安全区内、不相关信息之间。
不可接受的留白：
- 图幅过小造成的整片未用区域；
- 过大边距造成的空区；
- 页眉与主内容之间未使用的空带；
- 因文字被人为缩小而空出来的区域。

目标恒为：**有意的留白 + 高信息清晰度**。（与 §1.3 纵向分布规则配套执行。）

## §3 标题系统（Title System）

**同一视觉集内所有图片必须使用同一套标题系统。标题是视觉导航元素，不是摘要段落——只回答"这张图讲什么"，不用标题表达完整结论。**

### 3.1 标题长度（Title Length）
- 中文主标题：简单主题 4–12 字；确有必要时最多约 16 字。一个短短语或一句简明断言。
- 避免：长解释句、多从句、罗列详细证据、堆多个指标、"结论+解释"揉成一句。
- 原标题过长时处理顺序：① 找核心主题 → ② 删次级解释 → ③ 删冗余形容词 → ④ 把支撑结论移到副题 → ⑤ 标题只留核心概念。**禁止缩小字号迁就长标题**（§2.3/§2.4）。

### 3.2 标题 vs 副题（Title vs Subtitle）
- **标题**回答"What is this page about?"（本页讲什么）。
- **副题**回答"What is the key takeaway or context?"（关键结论 / 背景）。
- 不要把两者合并成一个长标题。示例：
  - Title：六年发布节奏
  - Subtitle：从首次众筹到平台化联名，每次新品都成为一次公开传播事件

### 3.3 统一标题格式（Consistent Title Format）
全套每一页同构：
```
[EN Section Label] · [Page Number]     ← kicker（EN 标签在前、页号 muted）
[Short Chinese Main Title]             ← h1（品牌主色）
[Optional Short Subtitle]              ← .sub（小号浅色）
```
示例：`GROWTH ENGINE · 03 / 09` + `双环增长飞轮` + `发布即增长，生态负责留存`。
标题的位置、层级、间距、对齐在全套内保持一致。

### 3.4 标题颜色（Title Color）
- 中文主标题必须用**品牌主视觉色**。确定来源：官网 → 官方视觉规范 → logo/品牌资产 → 其它可靠一手品牌物料；不随意取色（流程见 §9）。
- 品牌多色时，选主导主色用于主标题；**同一套图内不得在页间更换标题颜色**。

### 3.5 标题装饰条（Title Accent）
- 若系统带左侧竖条等装饰：竖条与主标题同色（同为 var(--c1)），装饰条 + 标题 + 品牌级元素形成一致的视觉身份。

### 3.6 标题层级（Title Typography Hierarchy）
- 三层顺序：EN Section Label（最小） → Main Chinese Title（最大最重、视觉主导） → Subtitle（明显更小更浅）。
- 副题不得与主标题"抢视觉"：小号、低字重、浅色；层级关系全套一致。

### 3.7 标题宽度（Title Width）
- 主标题约占页眉可用宽度的 **40–70%**。
- 避免：几乎横贯整幅画布；过短标题在空地上漂浮；生硬折行；3 行及以上。
- 目标 1 行，必要时 2 行，**禁止 3+ 行**。放不下时：先精简标题（3.1）→ 再调整可用标题宽度 → 最后才做小幅字号微调；禁止过度缩小标题。
- **副标题宽度必须与正文区一致（2026-09 用户反馈沉淀）**：`.sub` 不得设 `max-width` 收窄，它与 `.head` / `.content` 同 padding（各 72px），自然宽度 = 画布宽 − 两侧 padding（1600 画布 → 1456px）。窄于正文会让副标题缩在左半区、与下方内容右缘不齐，读起来"没铺开"。模板 `report-canvas.css` 中 `.sub` 现为 `max-width:none`，新页面不要改回固定值。

### 3.8 跨图一致性（Cross-Image Consistency）
- 定稿前并排比较全套标题：同位置、同对齐、同字体层级、同标题颜色、同装饰处理、相近视觉尺度、相近最大行数、与副题间距相近——标题要像同一份报告的页。

### 3.9 标题提炼优先级（Title Optimization Rule）
把研究段落压成视觉标题时用此优先级：
> Core Concept > Core Finding > Supporting Explanation

- 标题只放 Core Concept / Core Finding；
- Supporting Explanation 放进副题 / 注解 / 图表 / 证据 / 来源；
- **绝不超载标题**。

### 3.10 品牌名分档（v3 · 2026-09 沉淀）

"标题是否带品牌名"按**图位**分档，**不再要求每张都带**——旧版"全套主标题一律以品牌名开头"会挤压标题字数、让后续页标题变得僵硬重复。

- **首图（01）必须含品牌名**：如「Acme：某硬科技赛道的头部玩家」。首图是封面/头图/转发常被单独取用的一张，必须让人一眼知道在分析谁。**禁止**出现「私有硬科技巨头」这类看不出分析对象的标题。
- **其余各页不强制**：主标题按内容本身提炼（如「留存机制」「价格阶梯与品类矩阵」「口碑双面」「口径之争」），**靠「主标题 + 副标题」的组合把内容说完整**——副标题补足对象、结论或上下文（主标题「口碑双面」＋副标题「Acme 的拥趸与批评者在争什么」）。
- **判断标准**：主标题本身能读懂、且与首图的连续性足够 → 可省品牌名；主标题过于通用（如孤立的「增长引擎」，脱离上下文不知在说谁）→ **在副标题补品牌名/对象**，而不是硬塞回主标题。
- 品牌名进入主标题时计入字数，仍受 §3.1（≤16 字）与 §3.7（占页眉 40–70%）约束。

## §5 字体与排版

- 字体栈：`-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", "Noto Sans SC", Arial, sans-serif`。不要引入 web 字体（截图渲染依赖网络，易失败）。
- 数字优先清晰：大数字用 700/800 字重 + `font-variant-numeric: tabular-nums`。
- 字号阶梯（px，画布为 1600 宽基准）：显示数字 64–84；大标题 44–54；章节标签 30–32；正文 18–20；图例/标签 14–15；微注/徽章/chip 11–12.5。
- 行高：标题 1.1–1.2，正文 1.35–1.45，微注 1.4。
- 中文禁标点悬挂换行问题：标签保持整词断行。

## §6 图表编码规则（数字真实，图形只是比例示意）

- **可编码优先**：KPI 卡 / 条形组（`.bars`）/ 环形（conic-gradient，带图例与数值）/ 100% 分段条（`.segbar`）/ 时间线 / 流程 / 2×2 矩阵 / 对照表。数据不足（1–2 个孤立数、口径不可比）用 KPI 卡或短标签，不做假图表。
- **数值零改动**：每根条/每段弧旁边必须写**真实数值文本**（如 "30.8%"），图形长度/角度仅按组内最大值的比例示意；若数值差异极大导致某条太短看不清，可标注 `(≈n%) 过短，按比例仅示意`，不得改为等长。
- **口径纪律**：ESTIMATE 的数据一律在数据旁或图例注 `ESTIMATE`；机构口径差异大（如份额）加一行 "口径：xxx（机构），与其它机构口径存在差异"。UNKNOWN 项不画占位块。
- **换算**：如需人民币→美元等换算，图上标注 "按 1 USD≈7.1 CNY 换算（示意）"，并保留原数值单位。
- **排序**：**名义维度**（渠道 / 地区 / 平台 / 竞品）按数值**降序**；**序数维度**（价格档位 / 规模分层 / 时间 / 漏斗层级）**按固有顺序**，禁止按数值重排。**价格类一律由低到高**（入门在左、旗舰在右；报价制机型排最后并标注"报价制"）——价格轴是序数轴，读者默认单调递增。
- **时间口径**：图标题、轴标签、页脚来源里**禁用相对时间**（「上月」「近三个月」「过去 12 个月」「去年同期」）——图片会被单独转发，脱离报告后相对时间即失效。一律换绝对年月：`2026-08`、`2026 年 6–8 月`、`2025-09 – 2026-08`。来源只给滚动区间（`last month` / `last 12 months`）时，换算后须在页脚小而注里标明「按平台发布日推算，平台未公布绝对起止」。

### 组件速查
- **KPI 卡**：数值（大字）+ 单位/标签（小字）+ 可选 Δ/子注 + `SRC-xxx` chip + 证据徽章（右上角小徽章）。
- **条形组 bars**：`行 = 名称(宽 180px 左对齐) + 轨道(flex) + 数值(右, 700)`；名称≤12 字符。
- **100% 分段条 segbar**：整宽单条，段宽=占比；段内文字放得下才放（≥10% 放段内，否则放上方引出）。
- **环形 donut**：直径 170–220px；中心放总数；图例在右列逐项"色块 名称 数值"，≤6 段。
- **时间线 tl**：横向基线 + 节点（年份在上/下交错防重叠），每节点标题≤10 字 + 一行支撑数据；不要放长描述。几何硬约束见 §2.7。
- **流程 engine/flow**：3–6 个阶段块自上而下或自左而右，箭头用 CSS/SVG 简单描画；块内文字≤2 行；环回箭头标注关键词。几何硬约束见 §2.6。
- **矩阵**：2×2（如 impact × difficulty），横纵轴标签**定性**（低/中/高），点位标注短名与优先级；不得暗示数值精度。
- **对照表**：≤4 列、≤7 行，仅用于需逐行精确对照时（如价格阶梯）。

## §8 文本密度规则

- 主标题 4–16 字（标题系统 §3）；副题 ≤ 80 字符；正文块每行 ≤ 40 字符，最多 3 行；标签 ≤ 12 字。
- 每张图"可读结论"目标：3 秒扫出图在说什么，30 秒读完核心数字。
- **每页信息层 ≥4（§1.7）**：数据层 + 主视觉层 + 解读层 + 补充证据层，其中"解读层"为必含项——不要只摆数字。
- 长解释、方法论、深层分析留在原报告——图片不重复叙述。

## §9 品牌身份处理流程

1. 判断是否品牌专属。否 → 中性系统直接上。
2. 是 → 优先问用户要品牌色板/规范；没有则轻量探测官网：`curl` 首页 → 找主题自定义 CSS（如 `*.min.css`、含 `design`/`theme` 字样）→ 统计高频 hex，取出现最多且语义为"主交互/主品牌"的色为主色，再取 1–2 个高频辅色。记录出处（域名+文件+日期）供页脚或交付说明引用。
3. 主色通常用于：标题竖条、KPI 强调、主填充、页脚分隔；辅色用于次级块。文字色用深中性，不把亮色铺满背景。
4. 未验证到可靠色值 → 使用中性系统，并在交付说明中注明"未使用品牌色（未验证）"。**绝不凭记忆虚构品牌色**。

## §10 渲染与工具

- HTML 源：每图一个文件，放输出目录 `src_html/`，`<link rel="stylesheet" href="_sys.css">`；`_sys.css` = `assets/report-canvas.css` + 品牌令牌覆写（轮次参数）。
- 截图：`python scripts/shot_to_png.py <html1> <html2> ...`，输出同目录同名 `.png`（1600×1200@2x，自动发现 Chrome/Edge；可用 `--browser` 指定，`--scale` 覆盖，`--outdir` 换目录）。
- 几何探针：`node scripts/_geo.cjs <abs html1> <abs html2> ...`（每行输出一个 JSON）。**传参坑（2026-09 沉淀）**：不要用 shell 展开 `$(ls src_html/*.html)` 传参——在某些 shell/shim 下会传成空或畸形参数、回一堆空白 `{}` 行；**用显式绝对路径**，批量时最稳的办法是写个几行的 Python 包装脚本（`subprocess` 调 node、逐行 `json.loads`、打印 `fill/centerDelta/over` 并汇总 `ALL_OK` / `NEEDS_FIX`）。
- 每张 PNG 生成后必须人工目检一遍（Read 工具看图）：无越界/裁切/字重叠/数字笔误/徽章错色/风格漂移。
- 画廊：`index.html` 内嵌缩略图 `<img src="NN_x.png">` + 标题 + 一句话 + 该图口径注；单文件、无外链。
